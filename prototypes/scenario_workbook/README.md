## Run

From this folder, with the project environment:

```bash
../../.venv/bin/python -m pytest tests -q
```

About 130 seconds; test 4 and the LibreOffice recalculations take most of it. Reports land in `output/phase1/` to `output/phase4/` (git-ignored). Test 6's fixture tests read the Yellow Arrows fixture from `YA_FIXTURE_PATH` (an absolute path) and skip without it; every other test, including test 6's synthetic part, runs without it. The workbook tests (3, 6's workbook test, 8, 9, 10, 18) need LibreOffice and skip, with the reason, without it.

```bash
export YA_FIXTURE_PATH="/absolute/path/to/the fixture.xlsx"
../../.venv/bin/python -m pytest tests -q
```

With the fixture, `test_06_reproduce.py::test_pass_criterion` runs one test per scenario and spec section 9 criterion; a failure there is a reported mismatch with its likeliest cause in the message (detail in `output/phase3/reproduce_report.json`).

Build a workbook (synthetic data only until the live Richmond build; Richmond tuition stays null in `config/richmond.yaml`):

```bash
../../.venv/bin/python -m sw.build --config config/synthetic.yaml --data synthetic --seed 101 --scenarios config/scenarios_synthetic.yaml --out output/ --pdf
```

Build the reproduce-mode workbook from the fixture (Phase 3; output only under `output/`, which is git-ignored, because it holds fixture values):

```bash
../../.venv/bin/python -m sw.reproduce --out output/
../../.venv/bin/python -m sw.reproduce --out output/ --synthetic 101 --sentinel
```

The second line builds the synthetic reproduce workbook (no fixture; the one test 3 checks) as a sentinel copy for the desktop Excel check. The first writes `output/richmond_law/<plan_cycle>/<build_id>/workbook_reproduce.xlsx` and `output/phase3/reproduce_report.json` (settings, the fixture's detected counting rule, loader notes, lineage and pool sources, the cells not reproducible from the file with reasons, every criterion with the ledger's and the file's figure, cell-level differences with causes, and diagnostics), and prints the pass and fail counts per scenario, Scenario 4 first. `--sentinel` and `--pdf` work as for `sw.build`.

The live build writes `output/<client>/<plan_cycle>/<build_id>/workbook.xlsx` and, with `--pdf`, `workbook_Summary.pdf`; with `--sentinel`, `workbook_sentinel.xlsx`, whose every cached value is -999 (the copy for the desktop Excel check). The build id is a hash of the config, cell data, scenario file, `requirements.lock` and the generator code (`sw/*.py`, P21-03); two builds share it only if they are the same apart from RunLog's timestamp. RunLog lists the code hash, uncommitted files and whether the cached values are sentinels.

Mutation check (test 20; on demand, not collected by pytest):

```bash
../../.venv/bin/python tests/mutation_check.py --jobs 6
../../.venv/bin/python tests/mutation_check.py --excel --jobs 6
```

Set `YA_FIXTURE_PATH` (absolute path) so test 6's fixture tests run in every mutant copy. No test is deselected (R3-5).

It applies each mutant in `tests/mutation_check.py` to a scratch copy of the prototype (everything except `output/`) and runs the suite there. Python mode (default) runs every test with `SW_SKIP_EXCEL=1`: the workbook tests compare Excel with Python and would fail for any Python mutant, so they are left out. Excel mode (`--excel`) mutates formula strings in `sw/workbook.py` and runs tests 3, 6, 7, 8, 9, 18, 23, 26 and 27 with LibreOffice. `--deselect PREFIX` (repeatable) leaves tests out of every run, baseline included. The unmutated suite runs first in a copy made the same way and must pass; every mutant run must collect the same number of tests (else "count mismatch"); the report warns when one test accounts for more than half of the catches. Exit status is non-zero if any mutant survives that is not listed in `EQUIVALENT` with its reason. Reports: `output/mutation/report.json` and `report_excel.json`.

Desktop Excel parity (Phase 2 acceptance; by hand). Build the sentinel copy (`--sentinel` above), open it in Excel, let it recalculate, Save As a copy, then:

```bash
../../.venv/bin/python tests/compare_excel_saved.py path/to/saved_copy.xlsx
```

It refuses any file that is not a recalculated sentinel build of the current build id (P21-01): a normal build, a different build id, or a file whose every formula cell still holds -999. Otherwise it compares every formula cell with Python at test 3's tolerances, fails any cell still holding -999, compares each formula's text with the rebuild's (numeric literals by value), lists input cells edited since the build and prints the differences (report: `output/excel_check/<build_id>.json`, one file per build that no test overwrites; tests pass `--report` with a temporary path, R4-15). Reproduce builds (R3-3): build the sentinel copy with `sw.reproduce --sentinel` (fixture) or `--synthetic 101 --sentinel`; the script rebuilds from the fixture (`YA_FIXTURE_PATH` or `--fixture`) or the seed, also lists edited inputs on the Reproduce sheet, and reports the rounding probe on Checks, `ROUND(0.35/0.14, 0)`, whose argument is one binary step below 2.5 (Python and LibreOffice give 3; if Excel differs, follow Excel). Report: `output/excel_check/<build_id>_reproduce.json`. The older `output/phase2/` and `output/phase3/excel_compare_report.json` are no longer written (the Phase 2 one was overwritten by a test run before this fix). Test 3 checks that it passes a recalculated sentinel copy and fails the unopened sentinel build, a LibreOffice resave without recalculation, that resave with a Ledger formula replaced by `=0`, the normal build, and a recalculated copy with one formula typed over.

LibreOffice: `config/tools.yaml` holds `soffice_path` and `libreoffice_acceptance_version` (26.8.3.1; DECISIONS Nov 19, R4-17: the Checks rounding probe gives 2 in LibreOffice 24.2.7 and 3 in 26.8, so results depend on the engine version); RunLog records it and test 10 fails when the installed soffice reports another version. Env var `SOFFICE_PATH` overrides the path. Every call uses a fresh profile whose `registrymodifications.xcu` sets `OOXMLRecalcMode` to 0, so LibreOffice recalculates every formula on load.

## Metric names (methodology Appendix F)

`ntr_y1` (entering class, first year: `gross_y1` minus merit, need and specialty); `discount_entering_y1` (aid over `gross_y1`; Summary label "Discount rate (entering class, first year)"); `gross_y1` (enrolled times published first-year tuition; fees excluded); median margin at t (enrolled with a score at or above t minus enrolled with a score below t); share at or above t (over expected enrolled with a score); `E_S` (segment enrolled); incentive cost, paid-anyway share, aid per additional enrollee (Appendix F items 19 to 21); evidence share (item 24); step size (item 25). Ratios are ratios of expected values, E[X] / E[Y], everywhere.

## Policy choices stated here

- The shrink path trims unscored applicants first. This is a policy choice with access implications.
- Percentile targets (`score.percentile_targets`, v0.6.3): at most a share q of scored enrollees below t; the margin `q x N_scored - G-` counts swaps ("swaps: students below t who could replace students at or above t"); "approximate (fewer than 20 expected below t)"; the spread rows are a "band, not a score". GPA percentiles are not supported (one GPA boundary).
- One margin per event (R4-03, DECISIONS Nov 19): the median rows keep the at-or-above-minus-below margin; the percentile block, the Low/High rows and the class-size table leave out q = 0.5 targets (the median rows carry them). The pool strip still shows P for every percentile target (it has no percentile margin).
- Tie rule (R4-08): a median or percentile target holds when exactly a share q is below t; the ABA averages the two middle scores, so near a tie this can read a few points high. The spread band uses the same inclusive rule. The growth-to-date marker: a tie between two grid rows goes to the upper row (R4-13).
- `hold_position_rows` (R4-06; Richmond true until OD-14): every median and percentile figure on the Summary (rows, the share and count at or above a median or percentile t, the spread bands, the yield, pool and class-size strip columns, m_q, the narratives and the contract ranges) reads "held pending confirmation of the LSAT basis (OD-14)". It is a build setting, not an Inputs cell. Reproduce builds (validation only) are never held. The History 509 check, the Distribution sheet and the band counts (below the floor, admits cut by band) are not median or percentile figures and stay.
- Need aid (R4-07, OD-16): `need.total` scales with class (the rate per enrollee); a scenario's `need_total` departure from `need.total` is a fixed dollar amount, in live and reproduce modes.
- Break-even pool multipliers (R4-04) show a note instead of a number when the multiplier is not a pool size on the grid.
- Shrink-path segment protection: `trim.protect_segment` `below_threshold`, `above_floor` (Richmond: segment cells protected only from `score.floor` up to the first median threshold) or `none`.
- Revenue goal: `ntr_goal_basis` `entering_y1` (default) or `all_jd`, where `ntr_target` is the JD total and the figures read `ntr_target - continuing_ntr_usd` (continuing-student revenue as supplied by the client; attrition and renewals not modeled).
- Unscored enrollees are excluded from both sides of the median margins and reported as a count (`unscored_in_median: excluded`, the ABA 509 basis; reproduce mode uses the same rule, DECISIONS Nov 18).
- Range kinds are never combined: "90% outcome range" (enrollment noise and year-level variation, Middle case) and "Low and High price-response cases" (placeholder slopes now).
- While `shock_source` is `illustrative`, probabilities show as "under 5%" or "over 95%" beyond those bounds, beside "Year-to-year variation assumed (s = ...), not yet calibrated".

## Reproduce mode (Phase 3, spec section 9)

`python -m sw.reproduce` reads the fixture at run time (read only) from `YA_FIXTURE_PATH` and never writes a fixture value outside `output/`. The loader's rules are in the module docstring of `sw/reproduce.py`; in short:

- Cells come from the panel row labels (score part to `score_lo`, "<N" to the lowest configured band, another test or none to unscored; GPA part to hi, lo or blank). Several fixture GPA groups map to `lo`, so some cells share residency, score band and GPA class; cell ids keep them apart. Segments are blank (the file has residency only).
- Applications are admits / admit rate, rounded to whole applications. Where the admit rate is 0 or blank the applications are unknown: History shows them blank and the Ledgers read 0. Unknown base-cycle applications in a cell that some scenario admits students to are recovered from the scenario columns only when exactly one whole number fits every scenario's admits; otherwise the cell is "not reproducible from the file", left out of the pass criteria on both sides and counted (Reproduce sheet and report).
- Tuition by cohort and per scenario is award $ / award %. It lives in memory and in `output/`; `config/richmond.yaml` keeps tuition null (OP-8, OD-09).
- Lineage and the pool multiplier come from each scenario's description; specialty from its specialty row; need_total from config `need.total`, less any departure of the need row from the file's own need rule.
- Settings: `config/richmond.yaml` `reproduce:` block (`tuition_increase_pct` 6.0, `unscored_in_median` excluded, `round_apps_after_pool` true; DECISIONS Nov 18); integer admits and enrolled; mode reproduce. With `round_apps_after_pool`, applications are rounded to whole numbers after the pool multiplier, in reproduce mode only (Inputs `in_round_apps_after_pool`, read while the mode is Reproduce); live mode never rounds them (spec section 3). The loader detects the file's own counting rule from its count rows and reports it beside the setting.
- History carries a report-only ABA 509 reconciliation block (R3-4) per cohort: first-year class and the counts without a score or GPA (formulas), and whether each published LSAT and UGPA quartile lies in the range the band shares allow (computed at build). Figures come from the optional `aba_509_by_cohort` config key (public data; null for Richmond until entered). Checks reports one row per cohort; nothing is asserted.

Remaining differences, reported in `output/phase3/reproduce_report.json` (no figures here): only the non-reproducible cells (excluded from the criteria). Need aid in reproduce mode follows the file's rule (spec section 0A item B5): the need rate rounded to whole dollars per enrollee times the class, plus a scenario's `need_total` departure from `need.total` as a fixed amount; NTR now equals the file's in every scenario (the criterion stays within $100).
